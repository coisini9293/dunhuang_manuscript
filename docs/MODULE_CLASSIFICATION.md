# 敦煌数字保护工作台：模块迁移分类（Preview Sandbox）

> 本文件只用于预览阶段的结构规划。正式项目 `01_前端/敦煌前端/` 未被修改。

## 总体结构

预览阶段将当前单页中的内容整理为“首页叙事 + 历史档案 + 两个工具页 + 关于我们”五个入口。页面之间通过新建的导航和入口卡片建立跳转；现有工作台内部的控件、证据链和回放逻辑保留在独立工作台页面中，不在本阶段重写其业务逻辑。

| 预览页面 | 由当前内容迁移/承接 | 结构处理 | 不变约束 |
|---|---|---|---|
| 首页 `/index.html` | `.hero`、首页文案、三张背景图候选、功能入口、研究原则 | 首页只承载叙事与入口；主视觉采用左文右图、中心水墨羽化和纵向可滚动章节 | 现有首页文字不改；不把工作台塞回首页首屏 |
| 藏经洞历史 `/history/index.html` | 新增历史内容，依据 `assets/藏经洞历史.pdf` | 中轴时间线、交替节点、节点详情页 | 历史事实只取自 PDF；生成图仅作为“历史场景示意图” |
| 同源识别与智能缀合 `/rejoin.html` | `#module1`、上传/交换/旋转/替换/移除/回放控件 | 新增页面壳与导航，工作台仍是页面核心 | 保留现有 A/B 残卷操作逻辑与 replay 依赖 |
| 古卷证据约束修复 `/restoration.html` | `#module2`、证据探索、逐项裁决、批准区域、结果查看器、约束回放 | 新增页面壳与导航，按研究流程纵向分段 | 不改证据约束原则；不把自动结果写成学术结论 |
| 关于我们 `/about.html` | `#researchJourney`、`#dataProvenance`、项目原则 | “为什么做 → 我们怎么做 → 数据来源与项目原则”纵向叙事 | 六步流程可交互；真实内容必须回到出处 |

## 模块明细

### 1. 首页封面与导航

- 当前标题：`让离散的纸页 / 在证据中重逢`
- 当前 ID/位置：`#top`、`.hero`，入口为正式项目 `index.html`。
- 当前资产：`assets/video/hero.webm`、`hero.mp4`、`hero-poster.jpg`、`assets/generated/cave-library-conservation-desk.png`、真实残卷素材。
- 当前行为：`static/tonight-v3.js` 负责封面影片、工作台视觉状态和首屏互动；多个 CSS 文件负责纸张纹理、暖金色调、工作台视觉。
- 预览处理：保留文字，使用三张 `assets/background pics/` 图作为轮播主视觉；从画面中部向左做长距离、低对比度水墨/水彩羽化；提供至少三种羽化强度截图。
- 风险：AI 生成的水彩图不是证据材料；不能替代原有真实残卷和 replay 数据。

### 2. 同源识别与智能缀合

- 当前标题：`同源识别与智能缀合`。
- 当前 ID/位置：`#module1`，正式首页下半段。
- 当前资产/依赖：残卷 A/B 上传区、真实候选图、回放来源；`static/app.js` 中的 `/api/rejoin` 与候选/回放逻辑；`static/tonight-v3.js` 的旋转/交换/替换/移除/复位等行为。
- 预览处理：新建 `/rejoin.html`，顶部使用统一导航，纵向保留步骤条、控制条、双残卷工作台和结果区；工作台内部不以装饰图替代真实控件。
- 迁移风险：若直接抽取 DOM，可能丢失全局事件绑定和现有选择器；正式迁移时应先拆出共享工作台容器，再逐项迁移脚本依赖。
- 必须保留：上传、交换、旋转、缩放、平移、拼接/回放，以及当前真实数据与离线 replay 语义。

### 3. 古卷证据约束修复

- 当前标题：`古卷证据约束修复`。
- 当前 ID/位置：`#module2`，正式首页下半段。
- 当前资产/依赖：候选文字、证据记录、人工裁决、批准/拒绝/弃权、修复方案、专业结果查看器、约束修复回放；`static/app.js` 的证据/审阅/修复/replay 请求；`static/tonight-v3.js` 的查看器与结果状态。
- 预览处理：新建 `/restoration.html`，以“证据 → 逐项裁决 → 只收纳批准区域 → 结果查看 → 回放”纵向呈现。
- 迁移风险：证据链状态与 UI 状态耦合，不能只搬卡片而去掉原始出处、审计字段或人工状态。
- 必须保留：工作台作为真实审阅区；工程 PASS 不等于学术 PASS；单侧上下文不足时保持 abstain/不臆造。

### 4. 敦煌历史

- 当前项目状态：正式首页没有历史时间线，需要新建页面与内容模型。
- 内容来源：唯一正文依据 `assets/藏经洞历史.pdf`；PDF 的七个阶段为时间线节点来源。
- 预览处理：`/history/index.html` 使用居中轴线、左右交替节点、短说明、年份和一张“历史场景示意图”，节点点击进入 `history/event-*.html`。
- 约束：所有生成图仅放入 `preview-sandbox/assets/history-generated/`，并明确标注为生成示意，不冒充文物照片或证据图。

### 5. 关于我们与数据来源

- 当前内容：`#researchJourney`、`#dataProvenance`，以及原则性文字散落在多个 section。
- 预览处理：新建 `/about.html`，顺序固定为“为什么做 → 我们怎么做 → 数据来源与项目原则”；六步流程卡片在同一纵向章节中交互展开。
- 必须保留：项目目标是让失散残卷重新建立联系，不是让 AI 随意补字；真实内容可以回到出处。

## 跨页面共享依赖

- 共享视觉：米白纸张、朱砂、墨色、木质工作台、细线边框、衬线标题、低对比度网格/纸纹。
- 共享脚本：正式项目当前由 `static/app.js`、`static/art-direction.js`、`static/tonight-v3.js` 组成；预览阶段只复制/包裹，不改正式文件。
- 共享素材：原有 `assets/` 及三张 `assets/background pics/` 候选图；历史生成图只属于预览沙盒。
- 后端接口：`/api/rejoin`、`/api/cases/...`、证据、审阅、修复、replay 相关接口只在正式工作台页面中继续验证；预览静态页不伪造服务端成功状态。

## 本阶段不做的事情

1. 不修改正式 `index.html`、`static/`、`assets/`。
2. 不移动或覆盖原始图片。
3. 不执行正式 Loop 重构，不拆正式 React/Vue 组件，不改后端接口。
4. 不把生成的历史图当作文物证据。
